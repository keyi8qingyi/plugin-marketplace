---
name: draft-release-notes
description: Draft release notes from an explicit version range or supplied change list.
---

1. Use the requested revision range or provided change list. If the range is ambiguous, identify the available tags and ask which range to use.
2. Read the relevant commits and corroborating changes. Group user-facing changes by added features, fixes, and breaking changes.
3. Explain observable impact and any required migration steps. Include references when available. Omit empty groups and avoid claiming dates, compatibility or issue resolutions without evidence.
4. Return a draft for review. Leave publishing and tagging to the release owner.
